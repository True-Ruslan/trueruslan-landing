# MiniChess — Java domain logic case study

MiniChess — web-приложение для полноценной игры в шахматы на Spring Boot с серверной игровой логикой и browser UI.

## Контекст

Шахматы — хороший пример домена, где сложность находится не в форме CRUD, а в правилах и инвариантах: допустимость движения фигур, очередность, шах, атаки на короля и состояние партии.

**Стек:** Java 21 · Spring Boot 3 · Spring Web · Thymeleaf · JavaScript

## Архитектурный контур

```text
Browser UI
  │
  ├── ChessPageController → HTML / Thymeleaf
  │
  └── BoardApiController → REST API
          │
          ▼
      GameService
          │
          ▼
     Chess domain/core
```

Отдельные HTTP-контроллеры разделяют выдачу страницы и API игровой логики, а `GameService` концентрирует прикладное поведение игры.

## Что реализовано

- интерактивная шахматная доска;
- получение допустимых ходов для выбранной фигуры;
- серверная валидация хода;
- контроль очередности сторон;
- проверка, не оставляет ли ход собственного короля под шахом;
- определение состояния шаха;
- история ходов;
- reset новой партии;
- переворот доски в UI;
- REST API состояния доски и выполнения ходов.

## Инженерные решения

### Правила проверяются на сервере

Browser UI не является источником истины для игровой логики. Клиент может подсвечивать варианты и отправлять команды, но допустимость хода определяется backend-доменом.

### Домен отделён от transport layer

Контроллеры отвечают за HTTP/API, а игровая логика находится ниже. Это позволяет тестировать правила без привязки к браузеру и отдельно тестировать web-контроллеры.

### API отражает действия пользователя

Вместо одного универсального endpoint используются отдельные операции: получить доску, получить допустимые ходы, выполнить ход, получить историю, сбросить игру. Такой контракт проще читать и проверять.

## Проверяемость

В проекте заявлены отдельные тесты доски, `GameService`, REST-контроллера и page-controller. Maven-сборка поддерживает запуск тестов и генерацию JaCoCo report.
