# Project context entrypoint

Для быстрого восстановления контекста проекта использовать три canonical документа:

1. [`PROJECT_STATE.md`](PROJECT_STATE.md) — что представляет собой проект сейчас, архитектура, уже реализованные возможности, текущая работа и известный technical debt.
2. [`ROADMAP.md`](ROADMAP.md) — что делать дальше, в каком порядке и зачем.
3. [`CHANGELOG.md`](CHANGELOG.md) — смысловая история развития: что было сделано, когда, почему и каким способом.

## Рекомендуемый prompt для нового чата

> Открой в `True-Ruslan/trueruslan-landing` файлы `docs/PROJECT_STATE.md`, `docs/ROADMAP.md` и `docs/CHANGELOG.md`. Затем проверь актуальные open PR, последние commits и CI. Расскажи, что уже реализовано, что сейчас в работе, что изменилось после последнего state update и что оптимально делать следующим.

## Правило актуальности

Документы фиксируют понятный snapshot и долгосрочный контекст, но GitHub остаётся источником фактического текущего состояния.

При каждом новом продолжении разработки нужно дополнительно проверить:

- текущий `master`;
- open PR;
- последние merge commits;
- CI/workflow status;
- изменения, произошедшие после даты `PROJECT_STATE.md`.

После значимого product milestone, архитектурного решения или изменения roadmap эти документы нужно обновлять в том же PR или отдельным documentation PR.
